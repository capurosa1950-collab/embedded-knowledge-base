# 嵌入式底层常用通信协议联调与排错自查表 (Communication Checklist)

---

## 1. UART / 串口排查清单
* [ ] **TX/RX 交叉接线**：设备的 TX 必须接对方的 RX，RX 必须接对方的 TX（最常见低级失误）。
* [ ] **共地检查（GND）**：两台设备之间必须有可靠的信号地线连通，否则浮空电位差会导致数据全是 `0x00` 或乱码。
* [ ] **波特率偏差比对**：如果使用了内部 RC 振荡器（HSI），温漂可能导致波特率偏差超过 2~3%，引起乱码。建议使用外部晶振（HSE）。
* [ ] **硬件流控（RTS/CTS）**：如果在初始化中开启了硬件流控但硬件上并未连线，串口发送函数将永久阻塞等待 CTS 引脚。

---

## 2. I2C 总线排查清单
* [ ] **上拉电阻（致命核心）**：I2C 是开漏输出（Open-Drain），**必须**外接上拉电阻（通常 2.2K ~ 4.7K 到 3.3V）。若未接上拉，信号无法拉高。
* [ ] **7 位地址移位问题**：
  * 某些库（如 STM32 HAL 库）要求的参数是 **8位地址**（即 7位地址左移1位，第0位是读写位）。
  * 某些库（如 Arduino Wire）要求的参数是纯 **7位裸地址**。
* [ ] **I2C 挂死复位机制**：当从机在数据传输过程中异常复位，从机可能正把 SDA 拉低。此时主机无法产生起始条件。解决方法：主机配置 SCL 为普通 GPIO，连续翻转 9 个时钟脉冲，释放 SDA 总线。

---

## 3. SPI 总线排查清单
* [ ] **时钟极性（CPOL）与相位（CPHA）**：
  * Mode 0: `CPOL=0, CPHA=0` (空闲为低，第1个边沿采样) —— 最常用
  * Mode 3: `CPOL=1, CPHA=1` (空闲为高，第2个边沿采样)
  * 必须与从机手册的 Timing Diagram 严格对照。
* [ ] **CS/NSS 软件控制**：硬件 NSS 往往有隐形陷阱，推荐将 NSS 配置为普通 GPIO 推挽输出，在通信前拉低、通信完成后拉高。
* [ ] **全双工空写读取**：SPI 接收一个字节必须同时发送一个伪字节（如 `0xFF`），因为从机需要 SCK 时钟才能移出数据。

---

## 4. RS-485 差分总线排查清单
* [ ] **收发使能（DE/RE）延时**：发送完最后一个字节后，必须等待 **发送完成中断（TC 标志，Transmit Complete）**，才能拉低 DE 引脚切换为接收态；如果只检查 TXE（发送寄存器空中断），最后一个字节还没从移位寄存器发完就会被切断！
* [ ] **A/B 极性定义**：A 线为同相端（+），B 线为反相端（-）。某些厂商的标注相反（如 A/B 标注反转），可用万用表测量空闲电压：正常空闲时 A 应该略高于 B。
